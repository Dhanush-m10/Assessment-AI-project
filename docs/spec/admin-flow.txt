Question Generation
The system first searches the Question Library using:
* Skill Tags
* Difficulty Level
Questions can be retrieved regardless of whether the JD came from:
* JD Library
* AI Generated JD
The JD source should not affect the ability to use library questions.
If enough questions are available:
* Load questions from the Question Library
If enough questions are not available:
* Generate the remaining questions using AI
Example:
User requests 20 questions.
Library provides 15 questions.
System generates 5 additional questions using AI.
Additional requirement - System should track which library questions the users has previously correctly answered. For a period of 30 days, the same questions should not be asked. No requirement to track AI questions, those will only be stored in temporary memory. 

All AI questions generated should have a skill tracker attached, in order to reflect skill based percentage in the final report.

Job Title Tab — Required Changes
The hierarchy must be:
Category → Area → Job Title
The UI and filtering should consistently follow this hierarchy.
1. Hierarchical Filters
Add the following filters:
   * Category dropdown
   * Area dropdown
   * Job Title listing
The Category and Area filters must be placed on a separate line above the Job Title listing/content.
Filtering behavior
   * The user must select a Category first.
   * Before a Category is selected, the Area dropdown should be disabled or clearly indicate that a Category must be selected first.
   * Once a Category is selected, the Area dropdown should populate with only Areas belonging to that Category.
   * Include an “All” option where appropriate.
   * Once an Area is selected, display only Job Titles belonging to that Area.
   * If All Areas is selected for a Category, show all Job Titles belonging to Areas within that Category.
The flow should therefore be:
Select Category → Areas become available → Select Area → Job Titles are displayed
2. Status Filter
Keep the existing:
Live | Draft | All
   * Live must always be selected by default whenever the page is opened/refreshed.
   * Users can manually switch between Live, Draft, and All.
   * The status filter must work together with the Category and Area filters.
For example:
Category: Technology + Area: Software Development + Status: Live
→ Show only Live Job Titles under Software Development → Technology.
Category: Technology + Area: All + Status: Live
→ Show all Live Job Titles across all Areas under Technology.
Category: All + Area: All + Status: Live
→ Show all Live Job Titles across all Categories.

   * Inspect the existing frontend.

   * Inspect the Prisma/database schema.
   * Inspect existing assessment-related models.
   * Inspect the Python/FastAPI service.
   * Inspect existing OpenAI/AI generation functions.
   * Inspect authentication and user identification.
   * Inspect any existing question library implementation.

2. Architecture
The application architecture is:
   * Frontend / Main Backend: Next.js + TypeScript
   * API layer: Next.js API Routes
   * Database ORM: Prisma
   * Database: PostgreSQL
   * AI / processing service: Python + FastAPI
   * LLM provider: OpenAI
Use the responsibilities appropriately.
Next.js backend should handle:
   * authentication
   * authorization
   * user ownership
   * assessment lifecycle
   * database operations
   * question-library queries
   * question-history checks
   * JD library operations
   * assessment configuration
   * saving assessment attempts
   * saving answers
   * calculating or coordinating results
   * communication with FastAPI
FastAPI should handle:
   * AI question generation
   * AI coding-question generation
   * JD generation where applicable
   * JD skill extraction
   * structured AI processing
   * deterministic processing/scoring where appropriate
PostgreSQL should persist durable application data.
Do not use AI memory as a replacement for database persistence.

26. QUESTION REPLACEMENT — ALL FOUR FLOWS
Question replacement must be implemented consistently.
When Replace Question is clicked, exclude the current question and preferably all questions already present in the same assessment.
Priority:
   1. Question never attempted by the user
   2. Question previously answered incorrectly
   3. AI-generated replacement
Avoid questions answered correctly in the previous 30 days.
Never return the exact same question that the user just replaced.
Do not accidentally create duplicate questions inside the same assessment.
Replacement must maintain:
   * assessment type
   * question type
   * difficulty
   * appropriate skill
   * appropriate role/category context
For skill-focused assessments, try to replace a question with another question testing the same skill.
________________


27. QUESTION HISTORY — 30 DAY RULE
This rule is important.
For Question Library questions, track whether a user answered:
   * correctly
   * incorrectly
If the user answered a library question correctly during the previous 30 days:
Exclude it from normal generation and replacement where possible.
After 30 days it becomes eligible again.
Questions previously answered incorrectly may be reused.
Never-attempted questions have highest priority.
AI-generated questions do not require long-term question-history tracking.
The history filtering must happen server-side.
Do not download the full question library to the frontend and filter there.
________________

{
  "questions": [

      "skillId": "...",
      "options": [

Never trust raw AI output directly.

38. SKILL-BASED SCORE
Every scored question must be associated with at least one skill where skill scoring is expected.
Calculate:
Skill Percentage =
Correct Questions For Skill
/
Total Questions For Skill
× 100


Example:
SEO:
3 correct / 4 questions
= 75%
JavaScript:
4 correct / 5 questions
= 80%
Do not calculate skill percentages on the frontend from untrusted values.
Backend should return the final result.

    → Coding Library
    → AI fallback
    → Preview OR Start
    → Coding Assessment
    → Run / Submit Code
    → Results


These four paths are mandatory.

48. EDGE CASES
Handle at minimum:
   * Category has no Areas
   * Area has no Job Titles
   * Job Title has no default JD
   * JD has no extractable skills
   * AI extracts skill not present in Skill Library
   * User selects duplicate skills
   * Library has zero eligible questions
   * User correctly answered all available library questions in previous 30 days
   * Library only partially satisfies requested question count
   * AI question generation fails
   * AI returns malformed JSON
   * AI generates duplicate questions
   * assessment generation request is retried
   * question replacement is clicked multiple times
   * replacement pool is exhausted
   * user refreshes during preview
   * user refreshes during assessment
   * user leaves and returns
   * assessment is already completed
   * user attempts to submit twice
   * user tries to access another user's assessment
   * JD gets modified after an assessment was already generated
   * Question Library question gets edited after an assessment starts
   * Skill name changes after an assessment starts
Use snapshots where necessary so old assessments remain historically correct.
________________


49. DATABASE SEEDING / ADMIN DATA
Categories, Areas, Job Titles, Skills, default JDs, and library questions should be maintainable as database data.
Do not hardcode production taxonomy in React components.
If seed files already exist, extend them cleanly.
Ensure relations are created using stable IDs/slugs.
________________


50. PERFORMANCE
Question selection should be performed efficiently in PostgreSQL/Prisma.
Do not:
   1. retrieve the entire Question Library
   2. retrieve the entire user history
   3. filter everything in JavaScript
Use database filtering wherever practical.
Add indexes for commonly queried fields/relationships such as:
   * categoryId
   * areaOfInterestId
   * jobTitleId
   * skillId
   * difficulty
   * userId
   * questionId
   * completedAt / answeredAt
   * assessmentId
Choose exact indexes based on the final Prisma schema.
________________


51. SOURCE TRACKING
For every assessment question, know whether it came from:
   * QUESTION_LIBRARY
   * AI_GENERATED
   * CODING_LIBRARY
   * AI_CODING_GENERATED
This is required so that:
   * 30-day tracking applies correctly
   * AI questions are not incorrectly added to permanent history
   * replacement logic behaves correctly
________________


52. AI QUESTIONS ARE TEMPORARY
AI-generated questions should NOT automatically become permanent Question Library questions.
They belong to the generated assessment/attempt and may be stored as an assessment snapshot for persistence.
They do not need the same cross-assessment 30-day history tracking as library questions.
Do not accidentally pollute the permanent Question Library with every AI generation.
